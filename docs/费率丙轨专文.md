# 费率丙轨专文 · 强平成交与仓位边同步记账

> 本文只谈强平执行这一条写路径。结算封批、资金费率计提各有专文，
> 本文措辞不得整段外借到那两处，那两处的句子也不得整段搬进本文。

## 1. 口径选择：甲，不是乙

强平执行**只能走甲**：

- 甲：点执行即在同一事务内落正式强平成交，同时回写仓位边、升队列状态、重算保证金；
  任一步失败（含成交写不进去）整笔回滚，队列原地保持 `queued`。
- 乙：先落影子强平草案、正式成交与仓位零改、等确认后原子升正。

本仓明确**不实现乙**，也不允许甲乙混用：影子态（如 `shadow_draft`）不构成正式凭据，
不得据此把保证金行显示成 `liquidated`，更不得据此写 `fills` 或改 `positions`。

## 2. 「同步记账」到底同步什么

一次成功的强平执行，下列四边必须在**同一个事务**里一起出现：

| 边 | 表 | 关键字段 |
| --- | --- | --- |
| 成交 | `fills` | `source='liquidation'`、`note` 回指 `LIQ-xxxx`、`code=FIL-xxxxx` |
| 仓位 | `positions` | `qty` 扣减、`avg_entry`/`realized_pnl` 同步 |
| 队列 | `liquidation_queue` | `status='executed'`、`fill_code`、`remaining_qty` |
| 保证金 | `margin_states` | `used_margin` 按新仓位重算、`status` 由凭据推导 |

任何一边落单都不叫同步记账，叫事故。

## 3. 保证金状态的推导规则（禁止手写常数）

保证金状态不再由执行函数直接赋值，而是：

1. 用当前仓位 × 标记价重算 `used_margin` 与 `available`；
2. 扫强平队列：`executed` 行必须能通过 `fill_code`（或 `note` 回指）找到
   `source='liquidation'` 的成交；
3. 只有「存在正式强平成交」且「该簿仓位边已归零」时，页面才允许显示 `liquidated`；
4. 库内若残留无凭据的 `liquidated`，读取侧一律降级显示，并在联查接口报违规。

## 4. 失败即零增

- 成交写失败 → 仓位、队列、保证金全部不动，队列仍 `queued`；
- 仓位写失败 → 成交一并回滚，不出现「有成交无仓位」的半截账；
- 队列并发已被推进 → 后到者整笔回滚，并留争用痕。

## 5. 两处绿灯不许同源

写口红（执行成功）与对账绿（跨表账实一致）必须由**不同服务**给出：

- 写口：`backend/margin_svc.py` 的 `/api/margin/liquidations/{id}/execute`
- 对账：`backend/audit_svc.py` 的 `/api/audit/liq_recon`

对账接口只读，任何一次调用都不允许改正式区。
